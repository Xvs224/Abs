| **实际结果** | HTTP 401，message=无效的认证令牌 |
| **结论** | ✅ 通过 |

---

### TC-AUTH-05 登出

| 项目 | 内容 |
|------|------|
| **操作步骤** | 1. 学生登录获取 access_token + refresh_token<br>2. `POST /api/auth/logout`，body: `{"access_token":..., "refresh_token":...}`<br>3. 用同一 access_token 再次访问 `GET /api/auth/me` |
| **预期结果** | 登出返回 200；同 token 再访问返回 401 |
| **实际结果** | logout HTTP 200；reuse HTTP 401 |
| **结论** | ✅ 通过 |

> 注：登出接口要求在 body 中传入 `access_token` 和 `refresh_token`（二者均可选）。Token 被加入黑名单后无法再使用。

---

### TC-AUTH-06 权限隔离 — 学生访问管理员接口

| 项目 | 内容 |
|------|------|
| **操作步骤** | 用学生 token 调用 `POST /api/users`（创建用户，需管理员权限） |
| **预期结果** | HTTP 403，权限不足 |
| **实际结果** | HTTP 403，message=需要以下角色之一: admin |
| **结论** | ✅ 通过 |

> 注：`GET /api/users` 端点使用 `require_student_or_teacher`，学生和教师可访问（返回过滤后的用户列表），属设计行为。管理员专属接口为创建/更新/删除用户。

## 测试过程中发现的说明事项

| 编号 | 说明 | 性质 |
|------|------|------|
| 1 | 登录接口有频率限制（429），短时间内多次登录会被限流 | 设计行为，非缺陷 |
| 2 | 密码字段最少 6 位，不满足时返回 422 校验错误 | 设计行为，非缺陷 |
| 3 | 登出需传 access_token + refresh_token 到 body，而非仅靠 Header | 设计行为 |
| 4 | `GET /api/users` 允许学生/教师访问（返回过滤数据），非管理员专属 | 设计行为 |
